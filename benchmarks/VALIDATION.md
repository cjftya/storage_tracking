# 검증 기록

검증일: 2026-11-14 (Asia/Seoul). 환경: Windows 11 10.0.26300, Python 3.13.15, Tk 8.6. 저장매체 종류는 확인하지 않았으므로 SSD/HDD로 분류하지 않았습니다.

## 자동 및 통합 검증

```powershell
python -m unittest discover -s tests -v
python -m compileall -q storage_scanner tests benchmarks
```

- 총 39개 테스트: 38개 통과, 1개 건너뜀. 실제 심볼릭 링크 생성은 Windows 권한 제한으로 건너뛰었습니다.
- 실제 Windows junction으로 순환 경로를 구성해 재진입하지 않음을 확인했습니다. junction 자체를 검색 루트로 주어도 건너뜁니다.
- 권한 오류와 삭제 경쟁은 결정적인 모의 오류로 재현했습니다. 메타데이터 스캔 중 파일 내용을 여는 호출이 없음을 확인했습니다.
- Tkinter의 실제 위젯으로 20,000개 결과를 저장하고, 접힌 폴더의 지연 로딩·200개 페이지·갱신당 150개 삽입 상한을 검증했습니다.
- 20,000개 결과를 워커에서 배치 스트리밍하는 동안 Tk heartbeat 이벤트를 처리했고, 도중 취소 후 재시작한 최종 실행에 20,000개 결과가 정상 수집되었습니다. 이는 GUI/수집 경로의 부하 시험이며 디스크 파일 20,000개를 생성한 시험은 아닙니다.
- 실제 임시 폴더에서 GUI 검색·취소·재시작·완료 통계 표시를 확인했습니다. 이전 실행의 늦은 결과와 수집 오류도 별도 controller 테스트로 확인했습니다.
- Windows 볼륨 API 실행 결과 고정 볼륨 2개가 검색되었습니다. 테스트는 소유한 임시 폴더만 스캔했으며, 사용자의 전체 드라이브 스캔은 실행하지 않았습니다.

## 로컬 시나리오 측정

```powershell
python -m benchmarks.run_scenarios --entries 3000 --gui --output benchmarks/local-results.json
```

최종 엔진의 한 차례 로컬 측정입니다. 원시 JSON은 [local-results.json](local-results.json)에 있습니다. 각 모드는 새 프로세스에서 실행했습니다. 파일 생성 시간은 제외하고 캐시를 강제로 비우지 않았습니다. 다른 작업의 CPU/디스크 경쟁을 통제하지 않았고 캐시 영향도 있습니다. 환경 간 비교나 성능 보장을 위한 수치가 아닙니다.

| 시나리오 | 엔진 시간 | 저장 포함 시간 | GUI 내 엔진 시간 | GUI 전체 시간 | GUI 트리 갱신 누적 | GUI 최대 working set |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 빈 디렉터리 3,000개 (루트 포함 3,001개) | 0.243 s | 0.300 s | 0.285 s | 0.605 s | 0.061 ms | 45.7 MiB |
| 파일 3,000개, 일치 0개 | 0.0107 s | 0.00855 s | 0.0116 s | 0.608 s | 0.026 ms | 45.4 MiB |
| 파일 3,000개, 모두 일치 | 0.0228 s | 0.0474 s | 0.0734 s | 1.924 s | 3.349 ms | 46.5 MiB |

모든 모드에서 오류는 0개였습니다. 일치 3,000개 시나리오는 저장된 파일 3,000개, 화면 노드 201개(루트 + 첫 200개), 10ms heartbeat의 최대 실제 간격 약 94ms였습니다. GUI 전체 시간에는 700ms 갱신 대기가 포함되어 있습니다. 엔진 파일 처리량은 일치 없음 약 280,133 files/s, 모두 일치 약 131,373 files/s로 기록됐으나, 작은 캐시 친화적 fixture의 단일 측정이므로 실제 대형 스토리지 속도로 일반화하지 않습니다. 빈 폴더 시나리오의 files/s는 파일이 없으므로 0입니다.

초기 기준 측정 후 경로 키 생성의 별도 10,000회 측정에서 불필요한 전체 경로 해석 비용을 확인했습니다. 최종 코드는 이미 정규화된 절대 엔트리 경로의 재정규화를 줄이고, 상위 디렉터리를 통과한 파일은 정확한 파일 제외 경로만 확인합니다. 복잡한 캐시나 병렬 순회는 추가하지 않았습니다. 실행 간 캐시/부하가 달라 개선 배수는 산정하지 않았습니다.

## 아직 필요한 실기기 검증

- 이 환경에는 실행 가능한 WSL/Linux 설치가 없습니다. Linux mountinfo 파싱, 네트워크/가상 타입 거부, bind 별칭·중첩 마운트·btrfs subvolume 선택과 경로 경계는 자동 테스트로 검증했으며, Linux에서의 실제 GUI/마운트 순회는 검증하지 못했습니다.
- 실제 이동식 장치의 포함/제외, Windows 드라이브 문자 없는 볼륨, 실사용 네트워크 마운트, SSD/HDD별 대규모 디렉터리 성능은 별도 환경이 필요합니다.
- Linux에서는 `python3 -m unittest discover -s tests -v`와 위 시나리오 도구를 그래픽 세션에서 실행하고, 서로 다른 로컬 볼륨 및 제외된 네트워크 마운트에 크기 경계 파일을 배치해 한 번씩 집계되는지 확인하세요. 심볼릭 링크 순환도 실제로 검증하세요.

반복 측정과 실기기 검증 전에는 플랫폼 간 완료 시간이나 특정 속도 배수를 약속하지 않습니다.
